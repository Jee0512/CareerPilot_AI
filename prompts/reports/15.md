# Page UX Audit

## 1. `landing.py`
- **Purpose**: Initial landing experience and resume upload.
- **Primary CTA**: Upload Resume.
- **Duplicated UI**: The entire resume upload logic, parsing, and session state initialization duplicates `pages/upload_resume.py`.
- **Inconsistent UI**: Contains a custom HTML navbar that conflicts with Streamlit's native sidebar routing, creating two competing navigation mental models.
- **Recommendation**: Delete and make `upload_resume.py` the application home, or turn `landing.py` into a minimal dashboard.

## 2. `upload_resume.py`
- **Purpose**: Formal step 1 in the application workflow.
- **Primary CTA**: Continue to Job Description.
- **Current Visual Structure**: Clean native Streamlit file uploader.
- **Recommendation**: Promote to the default home route if `landing.py` is deleted.

## 3. `job_description.py`
- **Purpose**: Collect the target job description (text or URL).
- **Primary CTA**: Analyze Match.
- **Current Visual Structure**: Native `st.text_area` and `st.text_input`.
- **Recommendation**: Works well, requires no major UI changes.

## 4. `results.py`
- **Purpose**: Display the core semantic match between Resume and JD.
- **Information Hierarchy**: Match Score -> Missing Skills -> Present Skills.
- **Recommendation**: Convert the visualization to rely more heavily on the `.cp-ui` card system rather than disparate components.

## 5. `resume_optimize.py`
- **Purpose**: Fix resume gaps.
- **Primary CTA**: Download Optimized Resume / Apply Edits.
- **Recommendation**: Could benefit from a cleaner comparison grid (side-by-side) using `st.columns`.

## 6. `career_readiness.py`
- **Purpose**: Holistic career analysis (7-day plan, projects).
- **Primary CTA**: Explore recommended jobs.
- **Recommendation**: Complex layout with domain-specific HTML cards (`mentor_card`, `decision_card`). These are effective but need to strictly remain page-local to avoid component bloat.

## 7. `career_readiness_jobs.py` & `jobs.py`
- **Purpose**: Job exploration.
- **Duplicated UI**: Previously duplicated, now consolidated onto `render_job_card`.
- **Recommendation**: Excellent reuse of `render_job_card`. Combine these two pages if they serve the exact same user goal.

## 8. `interview.py` & `mock_interview.py`
- **Purpose**: Assessment collection.
- **Current Visual Structure**: Native Streamlit `st.radio` and `st.text_area` inside bordered containers.
- **Recommendation**: Highly accessible and responsive. Requires no custom UI wrappers.

## 9. `toolkit.py`
- **Purpose**: Additional AI generation tools (Email, Roadmap).
- **Recommendation**: Functions as a grid of distinct utilities. Good use of `st.container`.
# Application Flow Audit

## Current Journey
The user enters the application and sees two completely different navigation mental models:
1. The custom HTML top navbar in `landing.py` (Home, Features, Dashboard, Interview).
2. The native Streamlit sidebar injected by `st.navigation()` containing 11 distinct pages.

**Flow 1 (Through Landing)**:
`landing.py` -> Upload -> Switches to `job_description.py` -> Run Analysis -> Switches to `results.py`.

**Flow 2 (Through Sidebar)**:
User clicks `Upload Resume` in the sidebar -> Replicates exact same upload functionality -> Switches to `job_description.py`.

## Dead Ends & Confusions
- **Duplicated Uploads**: Having `landing.py` and `upload_resume.py` doing the exact same thing is a major anti-pattern.
- **Career Readiness vs Jobs**: `career_readiness_jobs.py` and `jobs.py` are distinct pages but they accomplish the same goal (rendering job recommendations). `career_readiness_jobs.py` feels like a dead end branching off the main flow.
- **Interviews**: `interview.py` and `mock_interview.py` are logically a two-step flow. Splitting them cleanly makes sense, but they should be grouped in the sidebar.

## Recommended Application Flow
The application should operate as a Workspace, not a marketing site.

1. **Workspace Entry**: The user opens the app and is immediately placed in the `Resume Workspace` (formerly `upload_resume.py`). `landing.py` is completely deleted.
2. **Analysis Pipeline**: Resume -> Job Description -> Match Results.
3. **Action Pathways**: Once results exist, the user can diverge into logical grouped actions:
   - **Improve**: Optimize Resume, Career Readiness
   - **Practice**: Interview Assessment, Mock Interview
   - **Explore**: Find Jobs, Career Toolkit

This flow eliminates redundant pages, groups related actions, and establishes a clear "Home" state where the user's resume is managed.
# Phase 15: Modern UI & Consolidation Audit

## 1. Executive Summary
The CareerPilot AI UI architecture has successfully transitioned from a fragmented collection of pages using raw HTML string concatenations into a unified `.cp-ui` design system. However, the overarching application flow and navigation structure still reflects its prototype origins (e.g. duplicating upload logic between a marketing "landing" page and a functional "upload" page). This audit defines the blueprint for Phase 16, focusing on consolidating the application shell, defining a strict Streamlit-native navigation hierarchy, and purging redundant pages.

## 2. Current Application Architecture
- **Routing**: `st.navigation()` is actively used in `app.py`.
- **Styling**: `tokens.css`, `base.css`, and `streamlit.css` provide global styles. Legacy stylesheets have been deleted.
- **UI Components**: Relying cleanly on `ui/components.py` for shared components (`render_job_card`, `render_circular_score`) and native Streamlit widgets for interaction.

## 3. Current Navigation Architecture
11 flat pages in the sidebar, with `pages/landing.py` forced as the default home. The landing page implements a fake top-navbar that contradicts the actual sidebar.

## 4. Recommended Information Architecture
The application must transition to a structured workspace with clear categories.
```python
pages = {
    "Workspace": [
        st.Page("pages/upload_resume.py", title="Home (Resume)", default=True),
        st.Page("pages/job_description.py", title="Target Job"),
        st.Page("pages/results.py", title="Match Results"),
    ],
    "Improve": [
        st.Page("pages/resume_optimize.py", title="Optimize Resume"),
        st.Page("pages/career_readiness.py", title="Career Readiness"),
    ],
    "Practice": [
        st.Page("pages/interview.py", title="Assessment"),
        st.Page("pages/mock_interview.py", title="Mock Interview"),
    ],
    "Explore": [
        st.Page("pages/jobs.py", title="Find Jobs"),
        st.Page("pages/toolkit.py", title="Career Toolkit"),
    ]
}
```
