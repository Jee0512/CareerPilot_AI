4. SIDEBAR DESIGN SYSTEM
==================================================

Design a premium CareerPilot sidebar consistent with the locked design system.

Visual principles:

- restrained
- clean
- highly readable
- generous whitespace
- clear active state
- no visual noise
- no unnecessary glassmorphism
- no excessive gradients
- no huge decorative elements

Use:

- existing design tokens
- existing typography scale
- existing spacing
- existing radius system
- existing semantic colors

Do not introduce new colors unless absolutely necessary.

The sidebar should communicate:

BRAND
Navigation
Primary workflow
Secondary tools
Start Over / utility actions

Use a clear hierarchy.

Do not make every navigation item look like a CTA.

Active navigation must be obvious but subtle.

Hover must be subtle.

Focus must be visible.

Touch targets must remain accessible.

- drag/drop
- hover

- invalid
- loading
- success

Style it only as far as Streamlit's supported/robust mechanisms allow.

### Select / Radio / Checkbox / Toggle

Inspect actual usage before creating styles.

Do not create visual styles for widgets that are not actually needed.

### Buttons

Establish:

Primary
Secondary
Tertiary / subtle
Destructive if actually required

Buttons must remain native Streamlit buttons when they trigger Python behavior.

Do not create fake HTML buttons.

==================================================
7. INPUT DESIGN PRINCIPLE
==================================================

Inputs are NOT cards.

Do not wrap every input in a giant decorative card.

Use hierarchy:

Section
→ label
→ control
→ helper/error text

Cards should communicate grouped information.

Inputs should communicate interaction.

This distinction is important.

==================================================
16. STREAMLIT CSS BOUNDARY
==================================================

Use normal CSS for:

- custom .cp-ui HTML
- stable presentation patterns

Use Streamlit-specific selectors only where needed to style native widgets.

When a Streamlit selector is unavoidable:

1. isolate it in styles/streamlit.css
2. add a comment explaining what it targets
3. avoid relying on implementation details unnecessarily
4. verify it against the current Streamlit version

Never scatter Streamlit DOM selectors across page files.
