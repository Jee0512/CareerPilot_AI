# 5. CUSTOM UI STRATEGY

There are three levels.

## LEVEL 1 — Native Streamlit

Use for:

* user input
* actions
* uploads
* forms
* navigation
* downloads
* stateful controls

---

## LEVEL 2 — `st.html()`

Use for static or presentation-heavy UI.

Examples:

* cards
* badges
* score displays
* visual metrics
* comparison layouts
* decorative sections
* custom typography blocks
* static status components
* visual skill representations

Prefer:

```python
st.html(...)
```

over:

```python
st.markdown(..., unsafe_allow_html=True)
```

for custom HTML presentation.

Do NOT continue expanding the old `unsafe_allow_html=True` architecture.

---

## LEVEL 3 — Streamlit Components v2

Use Components v2 ONLY when a UI element genuinely requires frontend capabilities that native Streamlit + `st.html()` cannot provide.

Examples:

* complex interactive editors
* rich text editors
* drag/drop interfaces
* complex client-side visualizations
* advanced interactive resume editing
* custom frontend state/events
* browser APIs
* sophisticated JavaScript interactions

Do NOT introduce Components v2 for:

* a card
* a badge
* a heading
* a score
* a static visualization

Components are an extension mechanism, not the default UI mechanism.
